## 子 Agent 委派

- 当任务有边界清晰、可独立推进的子任务，且主 Agent 能同时推进其他有效工作、预期收益超过协调成本时，主动委派，无需用户逐次点名。简单任务直接完成，不为使用不同模型而拆分。
- 根据歧义、推理深度、影响范围、可验证性和上下文依赖选择下表角色；这是初始策略，不是实测排名。无法明确分类的常规任务选 Terra，复杂契约或关键正确性疑点选 Astra。

| 角色（agent_type） | 模型 / 推理强度 | 适用任务 |
| --- | --- | --- |
| `luna-subagent` | `gpt-5.6-luna / max`（沿用已有配置） | 目标明确、边界很小、易验证的提取、整理、局部检查和重复工作 |
| `terra-subagent` | `gpt-5.6-terra / medium` | 常规探索、局部实现、测试分析、文档与接口核对 |
| `sol-subagent` | `gpt-5.6-sol / high` | 跨模块实现、复杂缺陷定位、需要持续执行与验证的多步骤工作 |
| `astra-subagent` | `gpt-6-astra / high` | 高歧义架构、复杂并发与状态、跨系统契约、关键正确性复核 |

- 使用当前工具已暴露的角色，通过 `agent_type` 选择，由角色 TOML 提供模型与推理强度，不重复覆盖。角色不可用时简要说明，并使用符合当前接口约束的可用替代方案；不自动修改配置。
- 委派前简要说明子任务及所选角色。提供自包含的目标、必要上下文、路径、权限边界、文件所有权和验收标准；并行写入范围不得重叠，明确要求保留其他操作者的修改。
- 子 Agent 默认不再委派。主 Agent 核对证据和验证结果，负责整合与最终验收；权限、网络和环境故障不直接作为升级模型的理由。更换执行者前先停止或等待原执行者结束，移交已有证据，避免重复重试。
- 本规则仅控制子 Agent，服从当前工具能力和更高优先级约束；不改变授权边界或主 Agent 模型，不将请求的模型名称当作实际运行模型已确认的证据。
